## 1. 문제 정의 — 난이도를 결정하는 것은 "오목함"이 아니다

가장 먼저 바로잡아야 할 오해가 있습니다.

> ❌ "도형이 오목(non-convex)하니까 면적 구하기가 어렵다"
> ✅ **오목한 것은 아무 문제가 아니다.** Shoelace 공식은 볼록/오목을 구분하지 않는다.

Shoelace는 **단순 다각형(simple polygon, 변끼리 교차하지 않음)** 이기만 하면 오목이든 볼록이든 정확합니다.
삼각형 분할도, 볼록 분해(convex decomposition)도 전혀 필요 없습니다.

그렇다면 난이도를 만드는 것은 무엇인가? **정확히 두 가지입니다.**

| 축 | 질문 | Yes면 필요한 것 |
|---|---|---|
| **① 순서** | 정점의 순회 순서를 모르는가? | 평면 그래프 + 각도 정렬 + face tracing |
| **② 교차** | 변끼리 서로 교차하는가? | 교차점 분할 + arrangement 구성 |

이 두 축의 조합이 난이도 표를 만듭니다.

| ① 순서 | ② 교차 | 필요한 것 | 코드 분량 |
|:---:|:---:|---|---|
| 안다 | 없다 | **Shoelace 한 줄** | 10줄 |
| 안다 | 있다 | winding number 해석 또는 arrangement | 200줄 |
| 모른다 | 없다 | 평면 그래프 + face tracing | 100줄 |
| 모른다 | 있다 | **arrangement 전체 (본 보고서의 종착점)** | 200줄 |

### 1.1 짚고 넘어갈 함정

**볼록 N각형 안쪽에 대각선(chord)을 그어도 바깥 컨투어는 변하지 않습니다.** 면적도 그대로입니다.

# Stage 0 — Orientation Predicate

## 0.1 이것 하나가 계산기하의 원자다

$$\text{orient}(A,B,C) = \operatorname{sign}\Big((B-A)\times(C-A)\Big)$$

외적의 부호가 세 점의 **회전 방향**을 말해줍니다.

- $> 0$ : 반시계 방향 (CCW), C가 직선 AB의 **왼쪽**
- $= 0$ : 세 점이 **한 직선 위** (collinear)
- $< 0$ : 시계 방향 (CW), C가 **오른쪽**

```cpp
static ll Cross(ll ax, ll ay, ll bx, ll by) { return ax * by - ay * bx; }

// A→B 를 기준으로 C 가 어느 쪽에 있는가
static int Orient(ll ax, ll ay, ll bx, ll by, ll cx, ll cy) {
    ll v = Cross(bx - ax, by - ay, cx - ax, cy - ay);
    return (v > 0) - (v < 0);
}
```

## 0.2 왜 이 값이 방향을 알려주는가

외적의 값 자체는 **두 벡터가 만드는 평행사변형의 부호 있는 넓이**이고, 동시에 $2\times2$ 행렬식입니다.

$$(B-A)\times(C-A) = \begin{vmatrix} B_x - A_x & C_x - A_x \\ B_y - A_y & C_y - A_y \end{vmatrix}$$

> **선형대수와의 연결**
> 행렬식 = 부호 있는 부피(면적). 이 해석을 손에 익히면 계산기하의 절반이 자연스러워집니다.
> "왜 하필 외적인가?"의 답은 **행렬식이 방향(orientation)을 보존하는 유일한 다중선형 함수이기 때문**입니다.

## 0.3 여기서 파생되는 모든 것

| 판정 | 방법 |
|---|---|
| 점이 직선의 어느 쪽인가 | `Orient` 1회 |
| **두 선분이 교차하는가** | `Orient` 4회 (양쪽 끝점이 서로를 가로지르는지) |
| 점이 선분 위에 있는가 | `Orient == 0` + 좌표 범위 체크 |
| 다각형이 CCW인가 | shoelace 부호 (Stage 1) |
| 볼록 껍질 (convex hull) | `Orient`로 좌회전만 유지 |

```cpp
// 정수점 (px,py) 가 선분 s 위에 있는가
static bool IsOnSegment(const Segment& s, ll px, ll py) {
    if (Cross(s.mBx - s.mAx, s.mBy - s.mAy, px - s.mAx, py - s.mAy) != 0) return false;
    return min(s.mAx, s.mBx) <= px && px <= max(s.mAx, s.mBx)
        && min(s.mAy, s.mBy) <= py && py <= max(s.mAy, s.mBy);
}
```

## 0.4 ✅ 통과 기준 / 연습

- [ ] 외적 부호만으로 두 선분의 교차를 판정할 수 있다 (끝점이 닿는 경우, 공선 겹침 포함)
- [ ] Convex hull (Andrew's monotone chain)을 직접 구현했다

# Stage 1 — 부호 있는 면적 (Signed Area)

## 1.1 Shoelace 공식

$$2A = \sum_{i=0}^{n-1}\left(x_i \, y_{i+1} - x_{i+1} \, y_i\right), \qquad i{+}1 \bmod n$$

부호가 방향을 알려줍니다. **CCW면 양수, CW면 음수.**

```cpp
using Point = pair<long long, long long>;

// CCW면 양수, CW면 음수. 2배 면적으로 유지해 정수 연산을 보존한다.
long long TwiceSignedArea(const vector<Point>& polygon) {
    long long acc = 0;
    int vertexCount = (int)polygon.size();
    for (int i = 0; i < vertexCount; ++i) {
        const auto& [x1, y1] = polygon[i];
        const auto& [x2, y2] = polygon[(i + 1) % vertexCount];
        acc += x1 * y2 - x2 * y1;
    }
    return acc;
}

double PolygonArea(const vector<Point>& polygon) {
    return llabs(TwiceSignedArea(polygon)) / 2.0;
}
```

**구현 주의:**
- 좌표가 크면 `long long` 필수 — `x1*y2`가 곱셈이라 **제곱 스케일**로 커집니다
- 답은 항상 `.5` 단위 → **`2A`를 그대로 들고 다니다 마지막에 나누는 것**이 안전합니다
- 부호를 버리지 말 것. CCW/CW 판정을 덤으로 얻습니다

## 1.2 왜 오목(non-convex)에서도 성립하는가

이 보고서에서 가장 중요한 직관 중 하나입니다.

각 항 $x_i y_{i+1} - x_{i+1} y_i$ 는 **원점 $O$와 변 $P_i \to P_{i+1}$이 만드는 삼각형의 부호 있는 면적의 2배**입니다.

- 다각형 **바깥** 영역: $+1$짜리 삼각형과 $-1$짜리 삼각형이 **정확히 상쇄**
- 다각형 **안쪽** 영역: winding number만큼 남음. 단순 다각형이면 $\pm 1$

오목 정점에서 "튀어나온 만큼 더 센 것"을 반대 부호 항이 정확히 깎아줍니다.
**볼록성은 어디에도 쓰이지 않았습니다.** 필요한 가정은 오직 "단순(simple)"뿐입니다.

## 1.3 연속 버전 — Green의 정리

Shoelace는 마법이 아니라 **Green 정리의 이산화**입니다.

$$\oint_{\partial D} \frac{x \, dy - y \, dx}{2} = \iint_D dA$$

경계선 적분이 내부 면적을 준다는 이 정리에서, 경계를 직선 조각으로 쪼개면 각 조각의 적분이 정확히 shoelace의 한 항이 됩니다.

> 이걸 알면 좋은 이유: **곡선 경계**로 확장할 때, 원호나 베지어에 대해 같은 적분을 하면 그대로 확장됩니다.

## 1.4 "안"이란 무엇인가 — Winding Number와 Jordan 곡선 정리

교차가 있으면 "안쪽"이라는 말 자체가 애매해집니다. 여기서 두 개념이 필요합니다.

**Jordan curve theorem** — 단순 폐곡선은 평면을 안과 밖 정확히 둘로 나눈다.
→ point-in-polygon이 애초에 well-defined인 **근거**이자, "단순하지 않으면 정의가 깨진다"는 **경고**입니다.

**Winding number** — 곡선이 어떤 점을 몇 바퀴 감았는가.
단순 다각형에선 안쪽이 $\pm1$, 바깥이 $0$. 교차하면 $2, -1, 3, \dots$이 나옵니다.

이때 채우기 규칙(fill rule)이 갈립니다.

| 규칙 | "안"의 정의 | 쓰이는 곳 |
|---|---|---|
| **nonzero** | winding $\ne 0$ | 일반적인 벡터 그래픽 기본값 |
| **even-odd** | winding이 홀수 | SVG `fill-rule`, 별 모양이 뚫려 보이는 그 규칙 |

⚠️ **교차하는 다각형에 shoelace를 그냥 쓰면 winding number 가중 면적이 나옵니다.**
winding 2인 영역은 2번 카운트되고, 8자 모양은 두 로브가 상쇄되어 0이 나옵니다.

## 1.5 보너스 — Pick의 정리

모든 정점이 격자점 위에 있는 단순 다각형이라면:

$$A = I + \frac{B}{2} - 1$$

($I$ = 내부 격자점 수, $B$ = 경계 격자점 수)

경계 격자점 개수는 `gcd`로 셉니다 — 변 $(dx, dy)$ 위의 격자점은 $\gcd(|dx|,|dy|)$개.

## 1.6 ✅ 통과 기준 / 연습

- [ ] Shoelace가 오목에서 성립하는 이유를 그림 없이 설명할 수 있다
- [ ] 부호로 CCW/CW를 판정하고, `2A` 정수를 유지한 채 구현했다
- [ ] winding number와 fill rule의 차이를 안다
- [ ] Pick의 정리로 같은 답이 나오는지 교차 검증했다

# Stage 2 — 평면 그래프의 위상 (순서를 모를 때)

> **여기가 진짜 관문입니다.** Stage 0·1은 공식이라 외우면 되지만,
> Stage 2는 "평면에 그려진 그래프의 조합적 구조"라는 **사고방식 자체가 새로** 필요합니다.

## 2.1 그래프 vs 매장(embedding)

- **평면 그래프(planar graph)** — 평면에 교차 없이 그릴 수 **있는** 추상 그래프
- **매장(embedding)** — 실제로 평면에 그려진 것. 같은 그래프도 여러 매장을 가짐

우리가 다루는 건 좌표가 주어진 **매장**입니다. 그리고 결정적인 사실:

> **평면 매장은 rotation system으로 완전히 결정된다.**

## 2.2 Rotation System

**rotation system** = 각 정점에서 나가는 간선들의 **순환 순서(cyclic order)**.

앞으로 짤 코드에서 "각 정점의 간선을 각도로 정렬"하는 부분이 정확히 이걸 계산하는 것입니다.
좌표는 정렬이 끝나면 위상 계산에서 더 이상 필요 없어집니다 — 면적 계산할 때만 다시 꺼냅니다.

```cpp
struct Dir { ll mX, mY; };

static int HalfOf(const Dir& d) {                       // 위/아래 반평면 분류
    return (d.mY < 0 || (d.mY == 0 && d.mX < 0)) ? 1 : 0;
}

static bool DirLess(const Dir& a, const Dir& b) {       // +x 축 기준 CCW 정렬
    int ha = HalfOf(a), hb = HalfOf(b);
    if (ha != hb) return ha < hb;
    return (i128)a.mX * b.mY - (i128)a.mY * b.mX > 0;   // 같은 반평면이면 외적
}
```

> **`atan2`를 쓰지 않는 이유:** 부동소수 오차로 정렬이 뒤집히면 face 구조가 **통째로** 깨집니다.
> 반평면 분류 + 외적이면 정수만으로 정확히 정렬됩니다.

## 2.3 DCEL과 Half-Edge

각 무향 간선을 **서로 반대 방향인 두 개의 half-edge**로 나눕니다.

```cpp
for (const auto& [u, v] : edgeSet) {
    heFrom.push_back(u); heTo.push_back(v);   // e   = u→v
    heFrom.push_back(v); heTo.push_back(u);   // e^1 = v→u  (twin)
}
```

인덱스를 연속으로 넣으면 **`e ^ 1`이 곧 twin**이 됩니다. 별도 배열이 필요 없어집니다.

이 구조의 정식 명칭이 **DCEL (Doubly-Connected Edge List)** 이고, 그래픽스 쪽에서는 half-edge 구조라고 부릅니다.

## 2.4 ★ 핵심 정리 (1) — `next`의 정의

> **`next(u→v)` = 정점 `v`에서 역방향 `(v→u)`의 CCW 각도 순서상 바로 *앞* 간선**

```cpp
auto NextHalfEdge = [&](int e) {
    int twin = e ^ 1;
    auto& list = outgoing[heFrom[twin]];       // CCW로 정렬되어 있음
    int k = slotOf[twin];
    return list[(k + (int)list.size() - 1) % (int)list.size()];   // 직전
};
```

이 규칙이면 **유계(bounded) face는 전부 CCW(양수 면적), 무한면만 CW(음수 면적)** 로 나옵니다.

### 손으로 검산해보기

삼각형 $A(0,0),\ B(1,0),\ C(0,1)$ 로 확인합니다.

**`next(A→B)`:**
B에서 나가는 간선 — `B→C` 방향 $(-1,1)$ = 135°, `B→A` 방향 $(-1,0)$ = 180°
CCW 정렬 → `[B→C, B→A]`. twin인 `B→A`는 슬롯 1. 직전은 슬롯 0 = **`B→C`** ✓

**`next(B→C)`:**
C에서 — `C→A` 방향 $(0,-1)$ = 270°, `C→B` 방향 $(1,-1)$ = 315°
정렬 → `[C→A, C→B]`. twin인 `C→B`는 슬롯 1. 직전 = **`C→A`** ✓

**`next(C→A)`:**
A에서 — `A→B` $(1,0)$ = 0°, `A→C` $(0,1)$ = 90°
정렬 → `[A→B, A→C]`. twin인 `A→C`는 슬롯 1. 직전 = **`A→B`** ✓

사이클 완성: $A{\to}B{\to}C{\to}A$, shoelace $= +0.5$ → **유계 face, CCW** ✓

반대쪽 사이클도 확인하면 $A{\to}C{\to}B{\to}A$, shoelace $= -0.5$ → **무한면, CW** ✓

Euler 검산: $V - E + F = 3 - 3 + 2 = 2$ ✓

## 2.5 ★ 핵심 정리 (2) — 연결 그래프면 음수 사이클은 정확히 1개

> **그래프가 연결되어 있으면 음수 면적 사이클은 정확히 하나이고, 그것이 최외곽 윤곽이다.**

**증명 스케치:** 연결 그래프에서는 유계 face가 구멍을 가질 수 없습니다.
구멍의 경계는 별도의 연결 성분이어야 하기 때문입니다.

따라서 다음이 성립합니다.

$$\text{윤곽 면적} = \big|\text{유일한 음수 사이클}\big| = \sum \text{모든 양수 사이클}$$

**이 등식이 공짜로 얻는 자체 검증입니다.**

```cpp
long double sumOfFaces = accumulate(result.mFaceAreas.begin(),
                                    result.mFaceAreas.end(), 0.0L);
assert(fabsl(sumOfFaces - result.mOuterArea) < 1e-6L);   // 연결 그래프일 때
```

> 이게 깨지면 십중팔구 둘 중 하나입니다.
> ① `NextHalfEdge`의 CCW 방향이 반대 ② 정점 중복 제거 실패(= 유리수 정규화 누락)
> **디버깅 순서도 이 둘부터.**

## 2.6 공짜로 따라오는 것들

**Dangling edge 자동 처리** — 가지 모양으로 튀어나온 간선(bridge)은 같은 face 안에서 왕복 순회되어 **면적이 정확히 0으로 상쇄**됩니다. 따로 제거할 필요가 없습니다.

**전체 부호합 = 0** — 모든 사이클의 부호 있는 면적을 더하면 항상 0. 또 하나의 검산.

**연결이 아닐 때** — 음수 사이클이 연결 성분 개수만큼 나옵니다. 한 성분이 다른 성분의 구멍 안에 들어앉았다면 대표점으로 point-in-polygon 검사를 해 최상위 것만 남겨야 합니다.
(다각형에 대각선을 그은 형태라면 **항상 연결**이므로 이 문제는 발생하지 않습니다.)

- [ ] `next`를 삼각형/사각형으로 손 검산했다

# Stage 3 — Arrangement 구성 (교차가 있을 때)

## 3.1 전체 파이프라인

| 단계 | 하는 일 | 비용 |
|:---:|---|---|
| 1 | 모든 선분 쌍의 교차점 계산 | O(N²) |
| 2 | 교차점에서 선분을 조각내기 (split) | O(N² log N) |
| 3 | 좌표 중복 제거 → 정점 ID 부여, PSLG 구성 | — |
| 4 | 정점마다 각도 정렬 → `next` 정의 (**Stage 2**) | — |
| 5 | 사이클 순회 = face 추출, shoelace (**Stage 1**) | O(E) |

Stage 4·5는 이미 배운 것입니다. **새로 필요한 건 1~3뿐**입니다.

## 3.2 왜 `double`을 쓰면 안 되는가

교차점은 일반적으로 **유리수**입니다. `double`로 두면 같은 점이 미세하게 다른 값으로 계산되어 **정점 중복 제거가 실패**하고, 그 순간 face 구조가 통째로 무너집니다.

> **면적이 조금 틀리는 게 아니라, 답이 완전히 다른 값이 됩니다.**
> 이 비선형성이 계산기하를 다른 알고리즘 분야와 갈라놓는 지점입니다.

해법: **분모를 들고 다니는 정확 유리수**.

```cpp
// (mXn/mDen, mYn/mDen), mDen > 0, gcd(|mXn|,|mYn|,mDen) == 1
struct RatPoint {
    ll mXn, mYn, mDen;
    bool operator==(const RatPoint& rhs) const {
        return mXn == rhs.mXn && mYn == rhs.mYn && mDen == rhs.mDen;
    }
};

// libc++(macOS clang)의 std::__gcd 는 부호 있는 타입을 거부한다 → 직접 정의
static ll GcdLL(ll a, ll b) {
    a = llabs(a); b = llabs(b);
    while (b) { ll t = a % b; a = b; b = t; }
    return a;
}

static RatPoint MakeRatPoint(ll xn, ll yn, ll den) {
    if (den < 0) { xn = -xn; yn = -yn; den = -den; }
    ll g = GcdLL(GcdLL(xn, yn), den);   // 정규형이라야 == 가 성립
    if (g > 1) { xn /= g; yn /= g; den /= g; }
    return RatPoint{xn, yn, den};
}
```

**정규화(gcd 축약 + 분모 양수화)가 핵심입니다.** 이게 있어야 `(2/4, 2/4)`와 `(1/2, 1/2)`가 같은 키가 됩니다.

> ⚠️ **macOS 함정 (이 저장소 환경에서 실제로 확인함)**
> `__gcd`는 libstdc++에서는 되지만 **libc++(Xcode clang)에서는 컴파일 에러**입니다.
> `std::__gcd`가 `static_assert(!is_signed<T>::value)`로 부호 있는 타입을 거부하기 때문입니다.
> PS 코드에 `__gcd`를 습관적으로 쓰고 있다면 로컬(mac)과 채점 서버(리눅스)의 동작이 갈립니다.
> `std::gcd`(C++17, `<numeric>`) 또는 위처럼 직접 정의하는 쪽이 안전합니다.

## 3.3 정확도의 분리 — 이 설계의 요체

| 계산 | 사용 타입 | 이유 |
|---|---|---|
| **위상** (같은 점인가, 이웃 간선인가) | `ll` / `i128` **정확 정수** | 틀리면 구조가 붕괴 |
| **면적 누적** | `long double` | 틀려도 그냥 오차 |

> **위상은 정확히, 면적은 근사로.** 이 분리가 견고한 계산기하 코드의 표준 설계입니다.

## 3.4 교차점 계산

선분 $s: A\to B$, $t: C\to D$ 에 대해:

$$\text{den} = (B-A)\times(D-C), \qquad u = \frac{(C-A)\times(D-C)}{\text{den}}, \qquad v = \frac{(C-A)\times(B-A)}{\text{den}}$$

$0 \le u \le 1$ 이고 $0 \le v \le 1$ 이면 교차. 교차점은 $A + u(B-A)$.

부호 처리 요령: `den < 0`이면 `den`, `numU`, `numV`를 **모두 부호 반전**한 뒤 `0 <= num <= den`으로 검사하면 나눗셈 없이 끝납니다.

## 3.5 공선 겹침(collinear overlap) 처리

`den == 0`인 평행/공선 케이스는 위 공식으로 처리할 수 없습니다. 대신:

> **"상대 선분의 끝점이 내 선분 위에 있으면 분할점으로 추가"**

이 한 줄이 T자 접촉, 공선 부분 겹침, 완전 중복을 **전부** 흡수합니다.
남는 중복 간선은 `set<pair<int,int>>`가 걷어냅니다.

```cpp
if (IsOnSegment(s, t.mAx, t.mAy)) sPts.push_back(MakeRatPoint(t.mAx, t.mAy, 1));
if (IsOnSegment(s, t.mBx, t.mBy)) sPts.push_back(MakeRatPoint(t.mBx, t.mBy, 1));
if (IsOnSegment(t, s.mAx, s.mAy)) tPts.push_back(MakeRatPoint(s.mAx, s.mAy, 1));
if (IsOnSegment(t, s.mBx, s.mBy)) tPts.push_back(MakeRatPoint(s.mBx, s.mBy, 1));
```

> 💭 논문 의사코드는 보통 "general position 가정"하고 이런 걸 생략합니다.
> **하지만 채점기는 안 봐줍니다.** 코드 길이의 상당 부분이 여기서 나오는 게 정상입니다.

## 3.6 오버플로 범위 — 반드시 손으로 계산할 것

입력 정수 좌표를 $|x|, |y| \le C$ 라 하면:

| 값 | 크기 |
|---|---|
| 분모 `mDen` | $\le 8C^2$ |
| 좌표 분자 `mXn` | $\le 24C^3$ |
| `MakeDir` 성분 | $\le 2 \cdot 24C^3 \cdot 8C^2 \approx 400C^5$ |
| `DirLess` 외적 | $\approx (400C^5)^2$ |

**$C \le 1000$ 인 경우:**
- `MakeDir` 성분 $\approx 3.8\times10^{17}$ → `long long` 안전 (한계 $9.2\times10^{18}$)
- `DirLess` 외적 $\approx 1.4\times10^{35}$ → `__int128` 안전 (한계 $1.7\times10^{38}$)
- **위 코드 그대로 OK**

**$C \le 10^4$ 인 경우:** `MakeDir`가 `long long`을 넘깁니다.
→ `Dir`를 `__int128`로 올리고 gcd 축약에 기대거나, 좌표를 스케일 다운하세요.

> ⚠️ 계산기하에서 오버플로 범위 계산은 **선택이 아니라 알고리즘의 일부**입니다.
> 문제를 풀기 전에 반드시 이 표를 손으로 채우세요.

## 3.7 두 가지 "윤곽 면적"

교차가 있으면 원하는 값이 정확히 무엇인지가 답을 가릅니다.

| | 정의 | 구현 |
|---|---|---|
| **(A) 최외곽 윤곽 내부** | 바깥 경계가 감싸는 전부, 구멍도 메움 | `mOuterArea` |
| **(B) 실제로 채워지는 영역** | fill rule로 "안"이라 판정된 face만 | `mFaceAreas` 필터링 |

**(B)** 가 필요하면 face마다 **대표 내부점**을 만들어 winding number를 계산합니다.

1. face의 half-edge 하나를 골라 중점 $M$
2. 진행 방향 $\vec{d}=(dx,dy)$의 **왼쪽 법선** $\vec{n}=(-dy, dx)$ 로 조금 민다
3. 유계 face는 CCW로 순회되므로 **왼쪽이 곧 내부**
4. $\varepsilon$은 그 face 최단 간선 길이의 $10^{-3}$ 정도

⚠️ 단, **간선 목록이 닫힌 경로를 이루지 않으면 winding number 자체가 정의되지 않습니다.** 그 경우 (A)만 의미가 있습니다.

# Stage 3-B — 특수 케이스: 볼록 위치 위의 닫힌 Hamiltonian Cycle

> ⚠️ **이 절은 본문 Stage 1~3의 기본값을 정정합니다.**
> 아래 수치는 전부 이 저장소에서 실제로 측정한 것입니다 (부록 F).

## 3B.0 문제 형태

- 정점 $N$개가 **원 위에 (= convex position)** 배치, 원형 순서 $1, 2, \dots, N$
- 간선 $N$개로 **닫힌 cycle**, 중복 방문 없음 → **Hamiltonian cycle**
- 간선끼리 교차 발생

$N=10$이면 서로 다른 cycle은 $9!/2 = 181{,}440$가지입니다.

## 3B.1 ★ 정정 (1) — 이 경우 순회 순서는 "아는" 것이다

Hamiltonian cycle은 **정점의 순열 그 자체**입니다. 즉 §1의 2×2 표에서 이 문제는

- ❌ "순서 모름 + 교차 있음" (Stage 2를 순서 복원용으로 쓰는 칸)
- ✅ **"순서 앎 + 교차 있음"**

에 해당합니다. **Stage 2의 face tracing은 여전히 필요하지만, 그 목적이 바뀝니다.**

| | 순서를 모를 때 | 이 문제 (순서를 알 때) |
|---|---|---|
| Stage 2의 역할 | **순회 순서 복원** | **face 분해** (winding 계산용) |
| 필요한가 | 예 | 예 — 다만 이유가 다름 |

## 3B.1-b 열거 의미론 — 순열 하나가 도형 하나가 아니다

**면적은 시작점 회전과 진행 방향 반전에 불변입니다** (실측 확인: 회전 9가지·반전 모두 동일).
따라서 하나의 도형에 **20개의 순열**이 대응합니다.

| 세는 대상 | 개수 ($N=10$) |
|---|---:|
| 순열(sequence) 전체 | $10! = 3{,}628{,}800$ |
| ÷ 시작점 회전 $N$가지 | $9! = 362{,}880$ |
| ÷ 진행 방향 2가지 | $\mathbf{9!/2 = 181{,}440}$ ← 서로 다른 도형 |

일반식: 서로 다른 Hamiltonian cycle 수 $= (N-1)!/2$.

> ⚠️ 문제가 **경우의 수**를 물으면 이 $\times 20$ 차이가 그대로 오답이 됩니다.
> 면적만 물으면 어느 대표 순열을 써도 상관없습니다.

## 3B.2 ★ 정정 (2) — `mOuterArea`는 이 문제의 답이 아니다 (75% 확률로 틀림)

**이것이 가장 중요한 정정입니다.**

닫힌 곡선이 자기교차하면 내부에 **winding = 0인 "빈 주머니"** 가 생깁니다.
`mOuterArea`는 최외곽 윤곽 안쪽을 **전부** 세므로 그 주머니까지 포함합니다.

**측정 결과 — $N=10$ 전수조사 (표본이 아니라 $9!/2 = 181{,}440$개 전부):**

| 현상 | 개수 | 비율 |
|---|---:|---:|
| winding = 0 인 내부 face 존재 | 135,378 | **74.613 %** |
| ⇒ `mOuterArea` ≠ nonzero-fill 면적 | 135,378 | **74.613 %** |
| nonzero ≠ even-odd | 145,151 | **79.999 %** |
| **raw shoelace ≠ nonzero** | 181,435 | **99.997 %** |

`raw == nonzero`인 예외는 **정확히 5개**입니다 — 볼록 10각형(볼록 위치에서 유일한
non-self-intersecting cycle) 하나와, 자기교차하지만 모든 면의 winding이 같은 부호 $\pm1$인 4개.

즉 **`mOuterArea`를 그대로 답으로 내면 4번 중 3번 틀립니다.**

### 실제 사례 — 세 값이 전부 다르다

방문 순서 `1 4 6 8 10 2 9 7 5 3` (반지름 1000 원 위 정10각형):

| 값 | 결과 | 비고 |
|---|---:|---|
| raw shoelace (winding 가중) | **51.0** | 거의 완전 상쇄 — 무의미 |
| `mOuterArea` (구멍 메움) | **2,528,332.8** | 정답의 **3.4배** |
| **nonzero fill** | **750,329.4** | 몬테카를로 독립 검증: 750,324.0 ✓ |
| even-odd fill | 750,329.4 | 이 사례에선 nonzero와 일치 |

> raw shoelace가 **51**입니다. 정답이 75만인데 51이 나옵니다.
> "작지만 그럴듯한 값"이라 **눈으로는 절대 못 잡습니다.** 반드시 검산하세요.

### 그래서 무엇을 출력해야 하는가

`ComputeContour`가 준 face들에 **winding number를 매겨 골라내야** 합니다. Stage 3.7의 (B) 경로입니다.

```cpp
long double nonzero = 0, evenodd = 0;
for (const auto& f : result.mFaces) {          // f = {면적, 대표 내부점}
    int w = WindingNumber(originalCycle, f.mRepX, f.mRepY);
    if (w != 0)     nonzero += f.mArea;        // nonzero rule
    if (w % 2 != 0) evenodd += f.mArea;        // even-odd rule
}
```

닫힌 cycle이므로 winding number가 **정의됩니다** — Stage 3.7의 단서 조건이 충족됩니다.

> 💭 **어느 규칙인가는 문제가 정해야 합니다.** 셋 중 하나이고, 측정상 80%에서 서로 다릅니다.
> 문제에 그림이 있다면 별 모양의 **중심이 칠해져 있으면 nonzero, 뚫려 있으면 even-odd**입니다.

### ✅ 결론 — 이 문제는 nonzero fill

원 문제의 조건이 **"별 모양의 중심이 칠해져 있다(= 겹친 영역이 존재한다)"** 로 확정되었습니다.

$$\boxed{\text{정답} = \sum_{\text{face}: \; w \ne 0} \text{면적}} \qquad \text{(nonzero rule)}$$

구현: [`Problems/GEOM_CONTOUR_AREA/`](../Problems/GEOM_CONTOUR_AREA/)

**단, "칠해진다"와 "겹친 만큼 센다"는 다릅니다.** 이 구분이 남은 마지막 함정입니다.

| 해석 | winding 3인 중심을 | 값 |
|---|---|---|
| 중심이 **칠해진다** | **1번** 센다 | **nonzero** ← 채택 |
| 중심을 **겹친 만큼** 센다 | **3번** 센다 | raw shoelace |

**{10/3} 오각별 실측** (방문 순서 `1 4 7 10 3 6 9 2 5 8`):

```
nonzero fill  : 2245236.0   <-- 채택
even-odd fill : 1980221.6
raw shoelace  : 4755486.0   <-- 2배 이상 차이
winding 분포  : w=-3 1개(중심), w=-2 10개, w=-1 10개
```

> 중심의 winding이 **3**입니다. nonzero는 1번, raw shoelace는 3번 셉니다.
> 문제에서 "겹친 부분을 두 번 더한다"는 표현이 나오면 nonzero가 아니라 raw shoelace입니다.
> 그런 문구가 없으면 nonzero가 맞습니다.

## 3B.3 ★ 누락 (1) — convex position이면 교차 판정이 조합 문제가 된다

본문은 **완전 일반 알고리즘**만 제시했습니다. 하지만 모든 점이 원 위에 있으면:

> **두 현 $(a,b)$, $(c,d)$가 내부에서 교차한다 $\iff$ 끝점이 원형 순서로 interleave 한다**
> (= $c$와 $d$ 중 정확히 하나만 호 $a\!\to\!b$ 안에 있다)

기하 연산이 **전혀 필요 없습니다.**

```cpp
// 원형 순서에서 x 가 lo 와 hi 사이에 (양 끝 제외) 있는가
auto Between = [&](int x, int lo, int hi) {
    int t = (x - lo + N) % N, h = (hi - lo + N) % N;
    return t > 0 && t < h;
};
auto ChordsCross = [&](int a, int b, int c, int d) {
    return Between(c, a, b) != Between(d, a, b);
};
```

**검증:** 정10각형의 끝점을 공유하지 않는 현 쌍 **1,260개 전부**에서 이 조합 판정이 `CollectSplitPoints`의 기하 판정과 **100% 일치**했습니다 (불일치 0).

교차 **여부**는 이걸로 O(1)에 끝납니다. 다만 교차 **좌표**는 여전히 유리수 계산이 필요하므로, arrangement를 만들 거라면 절약 폭은 제한적입니다. 교차 **개수**만 세면 되는 문제라면 기하 코드가 통째로 사라집니다.

## 3B.4 ★ 누락 (2) — 정다각형은 축퇴 지뢰밭이다

본문은 축퇴를 "가끔 나오는 예외"처럼 다뤘습니다. **정다각형에서는 규칙적으로, 대량으로 발생합니다.**

**측정:** 반지름 1000 정10각형에서 **주대각선 5개가 전부 원점을 정확히 통과**합니다.

```
대각선  1- 6 : ( 1000,    0)-(-1000,    0)  원점 통과 = YES
대각선  2- 7 : (  809, -588)-( -809,  588)  원점 통과 = YES
대각선  3- 8 : (  309, -951)-( -309,  951)  원점 통과 = YES
대각선  4- 9 : ( -309, -951)-(  309,  951)  원점 통과 = YES
대각선  5-10 : ( -809, -588)-(  809,  588)  원점 통과 = YES
```

일반 위치라면 교차점의 차수는 4입니다. 여기선 중심 한 점의 차수가 **최대 10**이 됩니다.

> ✅ **부록 A 코드는 이걸 견딥니다.** 전수 181,440개(주대각선 다수를 쓰는 cycle 포함)에서
> 자체 검증 등식이 깨진 횟수 **0회**. `MakeRatPoint` 정규화가 $k$중 교차를 자동으로 한 점으로 합칩니다.
> 하지만 축퇴를 안 다룬 구현이라면 **여기서 반드시 죽습니다.**

# Stage 4 — Sweep Line (최적화)

O(N²)를 $O((N+k)\log N)$ 으로 줄입니다 ($k$ = 실제 교차점 개수).

**바로 Bentley–Ottmann을 보지 말고 순서대로:**

| 순서 | 문제 | 배우는 것 |
|:---:|---|---|
| 1 | 1D 구간 합집합 길이 | 이벤트 정렬 + 상태 유지의 원형 |
| 2 | 최근접 점 쌍 (closest pair) | sweep + 후보 집합 관리 |
| 3 | 직사각형 합집합 면적 | sweep + segment tree |
| 4 | **Bentley–Ottmann** | ⚡ **이벤트 큐가 실행 중에 늘어나는** 첫 스위핑 |

> 4번에서 난이도 도약이 있습니다. 앞의 세 개는 이벤트가 미리 다 정해지지만,
> Bentley–Ottmann은 교차점을 발견할 때마다 큐에 **새 이벤트를 삽입**합니다.

💭 실전 조언: PS에서 $N \le 2000$ 정도면 O(N²)로 충분합니다.
Stage 4는 **정말 필요할 때** 오세요. 구현 난이도 대비 효용이 늦게 옵니다.

# Stage 5 — 강건성 (Robustness)

계산기하를 "그냥 알고리즘"과 갈라놓는 마지막 층입니다.

## 5.1 부동소수가 위상을 깨뜨리는 메커니즘

핵심은 **비선형성**입니다.

- 일반 수치 계산: 입력 오차 $\varepsilon$ → 출력 오차 $O(\varepsilon)$
- **기하 술어(predicate): 오차 $\varepsilon$ → `orient()` 부호가 뒤집힘 → face 구조 붕괴 → 출력이 완전히 무의미**

`orient()`가 딱 한 번 틀리면 사이클이 잘못 이어지고, 면적이 "조금" 틀리는 게 아니라 아예 다른 도형의 면적이 나옵니다.

## 5.2 EGC 패러다임

**Exact Geometric Computation** — *기하 술어(predicate)만 정확히 계산하면 전체 알고리즘이 정확해진다*는 원칙.

수치(좌표, 면적)는 근사해도 되지만 **판정(부호)은 정확해야 한다.** Stage 3.3의 설계가 정확히 이 원칙의 적용입니다.

## 5.3 더 공부할 것 (💭 아래는 기억 기반 — 출처 확인 필요)

| 주제 | 핵심 문헌 (미검증) |
|---|---|
| adaptive precision predicates | Shewchuk, *"Adaptive Precision Floating-Point Arithmetic and Fast Robust Geometric Predicates"* (1997경). `orient2d`/`incircle` 구현이 사실상 표준 |
| degeneracy 자동 처리 | Edelsbrunner & Mücke, *"Simulation of Simplicity"* (1990경) |
| 교차점을 격자에 스냅 | `snap rounding` — 위상을 보존하며 좌표를 유한 정밀도로 |

> ⚠️ 위 연도·제목은 **이 세션에서 검증하지 않았습니다.** 인용하기 전에 직접 확인하세요.

# 부록 A — 완성 구현

Stage 0~3을 모두 합친 실행 가능한 전체 코드입니다.
정수 좌표 $|x|,|y| \le 1000$ 기준으로 오버플로 안전합니다.

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll   = long long;
using i128 = __int128;

// ===== Stage 3: 유리수 좌표 점 =====
// (mXn/mDen, mYn/mDen), mDen > 0, gcd(|mXn|,|mYn|,mDen) == 1
struct RatPoint {
    ll mXn, mYn, mDen;
    bool operator<(const RatPoint& rhs) const {
        if (mXn != rhs.mXn) return mXn < rhs.mXn;
        if (mYn != rhs.mYn) return mYn < rhs.mYn;
        return mDen < rhs.mDen;
    }
    bool operator==(const RatPoint& rhs) const {
        return mXn == rhs.mXn && mYn == rhs.mYn && mDen == rhs.mDen;
    }
};

// libc++(macOS clang)의 std::__gcd 는 부호 있는 타입을 거부한다 → 직접 정의
static ll GcdLL(ll a, ll b) {
    a = llabs(a); b = llabs(b);
    while (b) { ll t = a % b; a = b; b = t; }
    return a;
}

static RatPoint MakeRatPoint(ll xn, ll yn, ll den) {
    if (den < 0) { xn = -xn; yn = -yn; den = -den; }
    ll g = GcdLL(GcdLL(xn, yn), den);
    if (g > 1) { xn /= g; yn /= g; den /= g; }
    return RatPoint{xn, yn, den};
}

// ===== Stage 0: orientation & 선분 =====
struct Segment { ll mAx, mAy, mBx, mBy; };

static ll Cross(ll ax, ll ay, ll bx, ll by) { return ax * by - ay * bx; }

static bool IsOnSegment(const Segment& s, ll px, ll py) {
    if (Cross(s.mBx - s.mAx, s.mBy - s.mAy, px - s.mAx, py - s.mAy) != 0) return false;
    return min(s.mAx, s.mBx) <= px && px <= max(s.mAx, s.mBx)
        && min(s.mAy, s.mBy) <= py && py <= max(s.mAy, s.mBy);
}

// s, t 의 분할점을 각각의 리스트에 추가
static void CollectSplitPoints(const Segment& s, const Segment& t,
                               vector<RatPoint>& sPts, vector<RatPoint>& tPts) {
    // (a) 상대 끝점이 내 선분 위에 있는 경우 — 공선 겹침까지 여기서 흡수
    if (IsOnSegment(s, t.mAx, t.mAy)) sPts.push_back(MakeRatPoint(t.mAx, t.mAy, 1));
    if (IsOnSegment(s, t.mBx, t.mBy)) sPts.push_back(MakeRatPoint(t.mBx, t.mBy, 1));
    if (IsOnSegment(t, s.mAx, s.mAy)) tPts.push_back(MakeRatPoint(s.mAx, s.mAy, 1));
    if (IsOnSegment(t, s.mBx, s.mBy)) tPts.push_back(MakeRatPoint(s.mBx, s.mBy, 1));

    // (b) 한 점에서 가로지르는 경우
    ll sdx = s.mBx - s.mAx, sdy = s.mBy - s.mAy;
    ll tdx = t.mBx - t.mAx, tdy = t.mBy - t.mAy;
    ll den = Cross(sdx, sdy, tdx, tdy);
    if (den == 0) return;                                       // 평행/공선 → (a) 가 처리
    ll numU = Cross(t.mAx - s.mAx, t.mAy - s.mAy, tdx, tdy);    // s 위 파라미터
    ll numV = Cross(t.mAx - s.mAx, t.mAy - s.mAy, sdx, sdy);    // t 위 파라미터
    if (den < 0) { den = -den; numU = -numU; numV = -numV; }
    if (numU < 0 || numU > den || numV < 0 || numV > den) return;
    RatPoint p = MakeRatPoint(s.mAx * den + sdx * numU,
                              s.mAy * den + sdy * numU, den);
    sPts.push_back(p);
    tPts.push_back(p);
}

// ===== Stage 2: 각도 정렬용 정수 방향 벡터 =====
struct Dir { ll mX, mY; };

static Dir MakeDir(const RatPoint& from, const RatPoint& to) {
    ll dx = to.mXn * from.mDen - from.mXn * to.mDen;   // 공통분모 곱해 정수화
    ll dy = to.mYn * from.mDen - from.mYn * to.mDen;
    ll g = GcdLL(dx, dy);
    if (g > 1) { dx /= g; dy /= g; }
    return Dir{dx, dy};
}

static int HalfOf(const Dir& d) {
    return (d.mY < 0 || (d.mY == 0 && d.mX < 0)) ? 1 : 0;
}

static bool DirLess(const Dir& a, const Dir& b) {          // +x 축 기준 CCW
    int ha = HalfOf(a), hb = HalfOf(b);
    if (ha != hb) return ha < hb;
    return (i128)a.mX * b.mY - (i128)a.mY * b.mX > 0;
}

// ===== 메인 =====
struct ContourResult {
    long double mOuterArea = 0.0L;      // 최외곽 윤곽이 감싸는 면적 (구멍 메움)
    vector<long double> mFaceAreas;     // 유계 face 각각의 면적
};

ContourResult ComputeContour(const vector<Segment>& segments) {
    int segCount = (int)segments.size();

    // --- 1. 분할점 수집 ---
    vector<vector<RatPoint>> splitPts(segCount);
    for (int i = 0; i < segCount; ++i) {
        splitPts[i].push_back(MakeRatPoint(segments[i].mAx, segments[i].mAy, 1));
        splitPts[i].push_back(MakeRatPoint(segments[i].mBx, segments[i].mBy, 1));
    }
    for (int i = 0; i < segCount; ++i)
        for (int j = i + 1; j < segCount; ++j)
            CollectSplitPoints(segments[i], segments[j], splitPts[i], splitPts[j]);

    // --- 2. 선분 조각내기 + 정점 ID ---
    map<RatPoint, int> vertexId;
    vector<RatPoint> vertices;
    auto GetVertexId = [&](const RatPoint& p) {
        auto it = vertexId.find(p);
        if (it != vertexId.end()) return it->second;
        int id = (int)vertices.size();
        vertexId[p] = id;
        vertices.push_back(p);
        return id;
    };

    set<pair<int, int>> edgeSet;                    // 중복 간선 제거
    for (int i = 0; i < segCount; ++i) {
        ll dx = segments[i].mBx - segments[i].mAx;
        ll dy = segments[i].mBy - segments[i].mAy;
        auto& pts = splitPts[i];
        sort(pts.begin(), pts.end(), [&](const RatPoint& a, const RatPoint& b) {
            // 방향으로의 사영 (x*dx + y*dy) 이 선분을 따라 단조 증가
            i128 ka = ((i128)a.mXn * dx + (i128)a.mYn * dy) * b.mDen;
            i128 kb = ((i128)b.mXn * dx + (i128)b.mYn * dy) * a.mDen;
            return ka < kb;
        });
        pts.erase(unique(pts.begin(), pts.end()), pts.end());
        for (size_t k = 0; k + 1 < pts.size(); ++k) {
            int u = GetVertexId(pts[k]), v = GetVertexId(pts[k + 1]);
            if (u != v) edgeSet.insert({min(u, v), max(u, v)});
        }
    }

    // --- 3. half-edge 구성 (e 와 e^1 이 twin) ---
    int vertexCount = (int)vertices.size();
    vector<int> heFrom, heTo;
    for (const auto& [u, v] : edgeSet) {
        heFrom.push_back(u); heTo.push_back(v);
        heFrom.push_back(v); heTo.push_back(u);
    }
    int heCount = (int)heFrom.size();

    vector<Dir> heDir(heCount);
    for (int e = 0; e < heCount; ++e)
        heDir[e] = MakeDir(vertices[heFrom[e]], vertices[heTo[e]]);

    // --- 4. 정점별 CCW 정렬 (= rotation system) ---
    vector<vector<int>> outgoing(vertexCount);
    for (int e = 0; e < heCount; ++e) outgoing[heFrom[e]].push_back(e);
    vector<int> slotOf(heCount);
    for (int v = 0; v < vertexCount; ++v) {
        auto& list = outgoing[v];
        sort(list.begin(), list.end(),
             [&](int a, int b) { return DirLess(heDir[a], heDir[b]); });
        for (int k = 0; k < (int)list.size(); ++k) slotOf[list[k]] = k;
    }

    auto NextHalfEdge = [&](int e) {                // ★ 핵심 정리 (1)
        int twin = e ^ 1;
        auto& list = outgoing[heFrom[twin]];
        int k = slotOf[twin];
        return list[(k + (int)list.size() - 1) % (int)list.size()];
    };

    // --- 5. face 순회 + shoelace ---
    vector<char> visited(heCount, 0);
    ContourResult result;
    for (int start = 0; start < heCount; ++start) {
        if (visited[start]) continue;
        long double twiceArea = 0.0L;
        int e = start;
        do {
            visited[e] = 1;
            const RatPoint& p = vertices[heFrom[e]];
            const RatPoint& q = vertices[heTo[e]];
            long double x1 = (long double)p.mXn / p.mDen, y1 = (long double)p.mYn / p.mDen;
            long double x2 = (long double)q.mXn / q.mDen, y2 = (long double)q.mYn / q.mDen;
            twiceArea += x1 * y2 - x2 * y1;
            e = NextHalfEdge(e);
        } while (e != start);

        long double area = twiceArea / 2.0L;
        if (area >  1e-12L) result.mFaceAreas.push_back(area);   // 유계 face
        if (area < -1e-12L) result.mOuterArea += -area;          // 무한면 경계
        // |area| ~ 0 : dangling edge 왕복 → 무시
    }
    return result;
}
```

# 부록 D — 언제 이 방법을 쓰지 말아야 하나

200줄 arrangement가 항상 정답은 아닙니다.

| 상황 | 권장 방법 | 분량 |
|---|---|---|
| 정점 순서를 안다 + 교차 없음 | **Shoelace** | 10줄 |
| 좌표 ≤ 수백의 정수 + 답이 정수 | **래스터화 + flood fill** | 30줄 |
| 격자 위 다각형 | **Pick의 정리** | 15줄 |
| 답을 정확히 요구 (분수 / 오차 $10^{-9}$) | **arrangement** (부록 A) | 200줄 |
| 실무 (PS 아님) | **라이브러리** (💭 CGAL / Boost.Geometry / Clipper2) | — |

**Flood fill 접근:** 좌표를 $K$배 확대해 선분을 Bresenham으로 래스터화 → 바깥에서 BFS → 안 칠해진 칸 수 $\times\, 1/K^2$.
교차점이 일반 유리수라 원 좌표계로는 정확하지 않지만, **답이 정수로 떨어지는 문제라면 $K = 2\sim4$로도 충분히 맞습니다.**
정확도를 포기하는 대신 구현이 30줄로 줄어듭니다.

> 💭 계산기하 문제는 **제약 조건이 의도된 풀이를 꽤 정확히 드러냅니다.**
> 좌표 범위와 $N$을 먼저 보고 위 표에서 칸을 고르세요.

**유리수 좌표 설계가 실제로 필요하고 실제로 동작한다는 증거입니다.**

## E.2 자체 검증 등식

`identity:ok` 열은 **Stage 2.5의 핵심 정리 (2)** 를 매 케이스마다 확인한 것입니다.

$$\sum \text{유계 face 면적} \;=\; \big|\text{무한면 사이클 면적}\big|$$

9개 전부에서 성립했습니다. 이 assert를 코드에 상시로 켜두세요 — **구현이 틀리면 거의 항상 여기서 먼저 잡힙니다.**

## E.3 테스트 하네스

```cpp
static int gFail = 0;

static void Check(const string& name, const vector<Segment>& segs,
                  long double expectOuter, vector<long double> expectFaces) {
    ContourResult r = ComputeContour(segs);
    sort(r.mFaceAreas.begin(), r.mFaceAreas.end());
    sort(expectFaces.begin(), expectFaces.end());

    bool ok = fabsl(r.mOuterArea - expectOuter) < 1e-9L
           && r.mFaceAreas.size() == expectFaces.size();
    if (ok)
        for (size_t i = 0; i < expectFaces.size(); ++i)
            if (fabsl(r.mFaceAreas[i] - expectFaces[i]) > 1e-9L) ok = false;

    // 핵심 정리 (2) : 연결 그래프면 sum(faces) == outer
    long double sumFaces = accumulate(r.mFaceAreas.begin(), r.mFaceAreas.end(), 0.0L);
    bool identity = fabsl(sumFaces - r.mOuterArea) < 1e-9L;

    printf("%-28s outer=%-10.4Lf faces=[", name.c_str(), r.mOuterArea);
    for (size_t i = 0; i < r.mFaceAreas.size(); ++i)
        printf("%s%.4Lf", i ? ", " : "", r.mFaceAreas[i]);
    printf("]  %s  identity:%s\n", ok ? "PASS" : "**FAIL**", identity ? "ok" : "**BROKEN**");
    if (!ok || !identity) ++gFail;
}

int main() {
    Check("square 10x10",
          {{0,0,10,0},{10,0,10,10},{10,10,0,10},{0,10,0,0}}, 100.0L, {100.0L});
    Check("square + diagonal",
          {{0,0,10,0},{10,0,10,10},{10,10,0,10},{0,10,0,0},{0,0,10,10}}, 100.0L, {50.0L, 50.0L});
    Check("L-shape (non-convex)",
          {{0,0,10,0},{10,0,10,5},{10,5,5,5},{5,5,5,10},{5,10,0,10},{0,10,0,0}}, 75.0L, {75.0L});
    Check("bowtie (self-intersect)",
          {{0,0,4,0},{4,0,0,3},{0,3,4,3},{4,3,0,0}}, 6.0L, {3.0L, 3.0L});
    Check("open X (no face)",
          {{0,0,10,10},{0,10,10,0}}, 0.0L, {});
    Check("square + dangling edge",
          {{0,0,10,0},{10,0,10,10},{10,10,0,10},{0,10,0,0},{10,10,15,15}}, 100.0L, {100.0L});
    Check("collinear overlap",
          {{0,0,10,0},{0,0,6,0},{4,0,10,0},{10,0,10,10},{10,10,0,10},{0,10,0,0}}, 100.0L, {100.0L});
    Check("square + both diagonals",
          {{0,0,10,0},{10,0,10,10},{10,10,0,10},{0,10,0,0},{0,0,10,10},{10,0,0,10}},
          100.0L, {25.0L, 25.0L, 25.0L, 25.0L});
    Check("rational xsect + dup edges",
          {{0,0,3,1},{3,1,3,0},{3,0,0,1},{0,1,0,0},{0,0,3,1},{0,1,3,0}}, 1.5L, {0.75L, 0.75L});

    printf("\n%s (%d failing)\n", gFail ? "SOME TESTS FAILED" : "ALL TESTS PASSED", gFail);
    return gFail != 0;
}
```

| 항목 | 값 |
|---|---|
| 정점 배치 | 반지름 1000 원 위 정10각형, 정수 반올림 (convex position 확인됨) |
| 범위 | **전수조사** — 첫 정점 고정(회전 제거) + 반사 정규화 = $9!/2 = 181{,}440$개 전부 |

## F.5 신뢰도에 대한 solid한 단서와 한계

**신뢰할 수 있는 근거:**
- $9!/2 = 181{,}440$이라는 **이론값과 실제 열거 개수가 일치** (열거 로직 자체의 검증)
- arrangement 기반 nonzero 면적이 **몬테카를로와 독립적으로 일치** (750,329.4 vs 750,324.0, MC 오차 범위 내)
- 불변식 `even-odd ≤ nonzero ≤ outer` 위반 **0회**
- 자체 검증 등식 위반 **0회**

**한계 (💭 명시):**
- 대표 내부점은 $\varepsilon = 10^{-7}$ 오프셋 휴리스틱입니다. 극단적으로 얇은 face에서는 이론적으로 오분류가 가능합니다. 위 불변식 검사가 그런 오분류를 대부분 잡아내지만 **증명은 아닙니다.**
- ~~표본 추정~~ → **전수조사로 대체됨.** 위 비율은 추정치가 아니라 $181{,}440$개 전부를 센 정확한 값입니다.
- 좌표는 정10각형을 정수로 **반올림**한 것입니다. 이상적 정10각형과 미세하게 다르지만, 주대각선 5개의 원점 통과(핵심 축퇴)는 **반올림 후에도 정확히 보존**됨을 확인했습니다.
