> ### 📄 2층 : 제약조건 → 케이스 기계적 변환

#### 1). 변수마다 5점을 찍는다

`1 ≤ N ≤ 100,000` 이면 → **`1`, `2`, 중간값, `99,999`, `100,000`**

* `min` : 기저 조건이 여기서 터진다
* `min+1` : 루프가 한 번은 도는 첫 지점
* `max-1`, `max` : 오버플로·시간 초과가 여기서 터진다
* 값의 범위가 음수를 포함하면 **`0`과 `-1`을 무조건 추가**한다

#### 2). 변수가 여러 개일 때 조합 폭발을 막는 법

전조합은 필요 없다. `N`, `M`, `K` 3개면 27개가 아니라 **8개면 충분**하다.

```
① 한 변수만 극단, 나머지는 대표값     -> 변수 개수 × 2 개
② 전부 최소                          -> 1개
③ 전부 최대                          -> 1개 (시간·메모리 검증 전용)
```

#### 3). 파생 제약을 놓치지 마라

지문에 직접 안 적힌 조건이 진짜 함정이다.

* **곱 제약** `N × M ≤ 1,000,000`
  → `N=1, M=10^6` / `N=1000, M=1000` / `N=10^6, M=1` 은 **모양이 전혀 다른 입력**이다.
  1×10^6 격자에서만 죽는 코드가 흔하다.
* **합 제약** "모든 원소의 합이 10^9 이하"
  → 개별 값은 작아도 누적에서 터진다. 개별 max가 아니라 **합이 max가 되는 입력**을 따로 만들어야 한다.
* **암묵적 보장** "그래프는 연결되어 있다"가 **없으면** 비연결 케이스를 만들어야 한다.

> ### 📄 2층 : 유형별 함정 카탈로그

문제 유형을 보고 해당 줄만 훑으면 된다.

| 유형 | 반드시 넣을 케이스 |
|---|---|
| 배열·정렬 | 원소 1개 / 전부 같은 값 / 이미 정렬됨 / 역정렬 / 중복 다수 / 음수·0 포함 |
| 누적합·구간 | 구간 길이 1 / 구간이 전체 / 왼쪽 끝·오른쪽 끝 경계 / 인덱스 0-based↔1-based |
| 그래프 | 정점 1개 / 간선 0개 / 자기 루프 / 다중 간선 / 비연결 / 완전그래프 / 방향 뒤집힘 |
| 트리 | 노드 1개(루트만) / **일자 트리**(재귀 깊이) / 별 모양(차수 폭발) / 리프가 루트인 경우 |
| 문자열 | 빈 문자열 / 길이 1 / 전부 같은 문자 / 앞뒤 공백 / 대소문자 / 최대 길이 |
| 기하 | 점 3개가 일직선 / 겹치는 점 / 좌표 음수 / 넓이 0 / 축에 평행한 선분 |
| DP | 초기값 도달 불가(`-INF` vs `0` 구분) / 답이 0인 경우 / 답이 음수인 경우 |
| 이분탐색 | 답이 `lo`인 경우 / 답이 `hi`인 경우 / 후보가 1개 / 만족하는 답이 없음 |
| 수 이론 | 0, 1, 2 / 소수 / 최대 소수 / 완전제곱수 / 음수 나눗셈(`-7/2`는 `-3`) |

**출력 형식**도 케이스다. 마지막 개행, 답이 없을 때 출력할 문자열, 실수 자릿수.

> ### 📄 오버플로 : PS 오답 1위

#### 1). 안전 범위

| 타입 | 대략 한계 | 넘는 대표 상황 |
|---|---|---|
| `int` | `2.1 × 10^9` | `10^5 × 10^5`, `10^5`개 × 각 `10^5` 합 |
| `long long` | `9.2 × 10^18` | `21!`, `10^9 × 10^9 × 10^9` |

#### 2). 캐스팅 **위치**가 핵심

```cpp
int a = 100000, b = 100000;
long long bad  = a * b;             // 1410065408  <- int로 곱한 뒤 승격, 이미 늦음
long long good = (long long)a * b;  // 10000000000 <- 곱하기 전에 승격
```

담을 그릇을 키워도 소용없다. **연산이 일어나는 시점의 타입**이 결정한다.

#### 3). 이 저장소는 이미 잡아준다

`Shell/*_Execute.sh`의 `-fsanitize=undefined,integer -fno-sanitize-recover=all` 덕분에
위 `bad` 줄은 실행 즉시 정확한 위치와 함께 죽는다.

```
ovf.cpp:5:24: runtime error: signed integer overflow: 100000 * 100000 cannot be represented in type 'int'
```

**그러니 최댓값 케이스를 만들어 돌리기만 하면 오버플로는 자동 검출된다.** 안 만들면 안 잡힌다.

> ### 📄 3층 : 스트레스 테스팅

가장 강력한 범용 기법. **정답 코드가 없어도** 반례를 찾는다.

#### 1). 파일 4개

```
gen.py     시드를 인자로 받아 랜덤 입력 생성 (재현 가능해야 함)
naive.cpp  느리지만 확실히 맞는 구현 (O(2^N) 완전탐색이어도 됨)
sol.cpp    검증할 진짜 풀이
stress.sh  둘을 돌려 diff
```

#### 2). 실제로 돌려본 예시

최대 부분합(Kadane)에서 `best`를 `0`으로 초기화한 흔한 버그를 심어두고 돌렸다.

```python
# gen.py  -- 작게! 반례를 눈으로 읽을 수 있어야 한다
import random, sys
rnd = random.Random(int(sys.argv[1]))
n = rnd.randint(1, 5)
print(n)
print(*[rnd.randint(-5, 5) for _ in range(n)])
```

```bash
# stress.sh
for i in $(seq 1 300); do
  python3 gen.py "$i" > in.txt
  ./naive < in.txt > out_naive.txt
  ./sol   < in.txt > out_sol.txt
  if ! diff -q out_naive.txt out_sol.txt > /dev/null; then
    echo "반례 발견 (seed=$i)"; cat in.txt
    echo "naive: $(cat out_naive.txt)  sol: $(cat out_sol.txt)"
    break
  fi
done
```

결과 — **2번째 시도에서 잡혔다.**

```
반례 발견 (seed=2)
1
-4
naive: -4  sol: 0
```

#### 3). 규칙 4개

1. **입력을 작게 만들어라.** `N ≤ 5`, 값 `-5..5`.
   크게 만들면 반례가 나와도 사람이 못 읽어서 쓸모가 없다. 위 반례가 `[-4]` 하나인 게 핵심이다.
2. **시드를 인자로 받아라.** 재현이 안 되면 디버깅을 못 한다.
3. **`naive`는 맞다는 확신이 있어야 한다.** 시간복잡도는 신경 쓰지 마라.
   정 못 짜겠으면 모든 경우를 나열하는 `next_permutation` / 비트마스크 완전탐색.
4. **반례가 나오면 더 줄여라.** 원소 하나씩 빼면서 여전히 틀리는지 확인 → 최소 반례.

> ### 📄 브루트포스를 못 짤 때 : 속성 검사

정답을 **몰라도** 틀렸다는 건 알 수 있다. 출력이 만족해야 할 성질을 검사한다.

| 문제 | 정답 없이 검사 가능한 성질 |
|---|---|
| 정렬 | 출력이 비내림차순 **그리고** 입력의 순열인가 (둘 다 봐야 함) |
| 최단경로 | 모든 간선 `(u,v,w)`에 대해 `d[v] ≤ d[u] + w` |
| MST | 간선 수가 `V-1`인가, 사이클이 없는가, 연결인가 |
| 최대매칭 | `answer ≤ min(|L|, |R|)` |
| 유량 | 각 정점에서 유입 = 유출, 각 간선에서 `flow ≤ capacity` |
| 압축·인코딩 | `decode(encode(x)) == x` (역연산 검증) |
| 조합·경우의 수 | 작은 `N`에서 손계산 값과 대조, 점화식 `f(n)`과 `f(n-1)` 관계 |

**메타모픽 검사**도 유용하다 — 입력을 바꿨을 때 답이 **어떻게 변해야 하는지**로 검증한다.

* 입력 순서를 섞어도 답이 같아야 한다 (순서 무관 문제)
* 모든 좌표에 `+1000` 해도 답이 같아야 한다 (평행이동 불변)
* 원소를 하나 추가하면 답이 줄어들 수 없다 (단조성)

> ### 📄 이 저장소에서 굴리는 법

#### 1). 파일 규약

```
Problems/<문제>/InputQuerys/input_NN_이름.txt   # 입력
Problems/<문제>/Expected/input_NN_이름.out      # 기대 출력 (독립 생성)
```

`SWEA_Execute.sh`는 `InputQuerys/` 안의 파일을 **알파벳 순으로 전부** 순회하므로
`input_01_`, `input_02_` … 로 번호를 붙이면 순서가 보장된다.

**크래시가 예상되는 케이스는 반드시 파일을 분리한다.** 한 파일에 여러 TC를 몰아넣으면
앞에서 죽는 순간 뒤 케이스가 통째로 날아간다.

#### 2). 기대 출력은 프로그램 출력을 베끼지 마라

내 코드 출력을 `expected`로 저장하면 **버그까지 정답으로 굳는다.**
Python이나 별도 구현으로 **독립 생성**해야 의미가 있다.

```bash
for e in Expected/*.out; do
  n=$(basename "$e" .out)
  ./main "InputQuerys/$n.txt" 2>/dev/null | diff -q - "$e" > /dev/null \
    && echo "PASS  $n" || echo "FAIL  $n"
done
```

#### 3). 빌드 플래그가 잡아주는 것 (`Shell/*_Execute.sh`)

```
-fsanitize=undefined,integer -fno-sanitize-recover=all      # UB·오버플로 즉시 중단
-fno-sanitize=unsigned-integer-overflow,unsigned-shift-base # unsigned 오탐 제외
-D_LIBCPP_HARDENING_MODE=_LIBCPP_HARDENING_MODE_DEBUG       # STL 범위·불변식 검사
```

##### ① STL 범위 초과

UBSan만으로는 **컨테이너 범위 초과를 못 잡는다.** `vector<int> v(3); v[5]` 실측:

| 빌드 | 결과 |
|---|---|
| UBSan만 | `0` 출력하고 **그냥 통과** |
| `+ HARDENING=DEBUG` | `libc++ Hardening assertion __n < size() failed: vector[] index out of bounds` |

##### ② 비교자가 strict weak ordering을 어기는 경우

`sort`에 `return a <= b;` 를 넘기는 실수(`<` 여야 함). 하드닝 모드별 실측:

| 모드 | 결과 |
|---|---|
| `NONE` | **무한 루프** (10초 타임아웃) |
| `FAST` / `EXTENSIVE` | `SIGTRAP`(133) — 메시지 없이 죽음 |
| `DEBUG` | `Would read out of bounds, does your comparator satisfy the strict-weak ordering requirement?` |

원인을 바로 짚어주는 건 `DEBUG`뿐이라 `DEBUG`를 쓴다.
`sort(2×10^6)` + `operator[] 2×10^6`회 기준 하드닝 오버헤드는 측정 노이즈 수준이었다.

##### ③ `-fsanitize=integer`의 오탐 주의

`integer` 그룹에는 **unsigned 오버플로·시프트**가 들어 있는데, 이건 UB가 아니라
**규격에 정의된 wraparound**다. 그래서 아래가 전부 오탐으로 죽는다.

* `mt19937` / `shuffle` — `left shift of ... cannot be represented in type 'unsigned int'`
* 해시 함수의 의도된 `unsigned long long` 곱셈 오버플로

`-fno-sanitize=unsigned-integer-overflow,unsigned-shift-base` 로 이 둘만 빼면
**signed 오버플로 검출은 그대로 유지된다**(실측 확인). 스트레스 테스팅에 `mt19937`을
쓰려면 이 한 줄이 반드시 필요하다.
